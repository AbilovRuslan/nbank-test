# 5. Отчёт: параллельный запуск UI-тестов

## Внесённые изменения для многопоточности

1. **Изоляция тестов.** Каждый UI-тест создаёт собственного пользователя через `AdminSteps.createUser()` и выполняет авторизацию через `authAsUser()`. Тесты не используют общего пользователя между потоками.
2. **Убран `@UserSession` из тестов, где он создавал общее состояние.** Создание пользователя и авторизация выполняются непосредственно внутри теста через вспомогательный метод `createUser()`.
3. **Исправлен `SessionStorage`.** Для хранения пользовательских данных используется `ThreadLocal`, благодаря чему каждый поток получает собственный экземпляр `SessionStorage` и не пересекается с данными другого потока.
4. **Исправлена работа с UI-алертами.** После создания аккаунта добавлено корректное закрытие браузерного alert, чтобы следующий UI-шаг не блокировался.
5. **Настроен параллельный запуск JUnit 5.** Тесты разрешено выполнять параллельно, количество одновременно выполняемых потоков задаётся настройкой `fixed.parallelism`.
6. **Настроен Selenoid.** Для параллельного выполнения UI-тестов доступно до 5 браузерных сессий одновременно.

## Замеры

| Конфигурация | Кол-во потоков | Время старта приложения | Время чистого прогона тестов | Общее время выполнения |
|---|---:|---:|---:|---:|
| Последовательный запуск | 1 | — | — | **115 с** |
| Параллельный запуск | 3 | — | — | **81 с** |
| Параллельный запуск | 5 | — | — | **40,841 с** |

> Время старта приложения и время чистого прогона отдельно не были зафиксированы в исходных замерах, поэтому они обозначены `—`. Общее время взято из вывода Maven (`Total time`).

# 6. Выводы

1. Лучший результат получен при **5 потоках** — общее время выполнения составило **40,841 с**.
2. При последовательном запуске тесты выполнялись примерно **115 с**.
3. При 3 потоках время составило примерно **81 с**.
4. При 5 потоках время сократилось до **40,841 с**, то есть ускорение относительно последовательного запуска составило примерно **2,8 раза**.
5. Основное ограничение для UI-тестов — количество доступных параллельных браузерных сессий Selenoid. В конфигурации используется лимит **5 браузеров**, поэтому увеличение количества потоков выше 5 не даст пропорционального ускорения.
6. Параллельный запуск показал существенное сокращение времени выполнения при сохранении результата **BUILD SUCCESS**.
